How to track SSL certificate expiry in Jira

An expired certificate takes a site down for everyone at once, and it usually happens to a certificate nobody remembered: an internal tool, a load balancer, a host that was set up by someone who has left. This guide shows three ways to get a Jira issue before a certificate expires, from free and manual to automatic.

What a good reminder needs

  • The real date. A date typed into a spreadsheet is wrong the day someone renews early or reissues the certificate. The date should be read from the certificate itself.
  • An owner. A reminder that goes to a shared mailbox is read by nobody. It should be assigned to one person.
  • Enough time. Seven days is fine for Let's Encrypt. A certificate that needs a purchase order needs 30 or 60.
  • Internal hosts. Many of the certificates that get forgotten are not reachable from the internet.

Option 1: read the date yourself and set a due date

For a handful of certificates this is enough. Read the expiry date with openssl:

echo | openssl s_client -connect portal.example.com:443 -servername portal.example.com 2>/dev/null \
  | openssl x509 -noout -enddate

Create a Jira issue per certificate, set the due date a few weeks before the printed date, and assign it.

What goes wrong: the issue is closed after the renewal and nobody creates the next one, and nothing notices when a certificate is replaced with one that expires earlier.

Option 2: a script and Jira automation

Run the command above from cron for a list of hosts, compare the date with today, and call a Jira automation "incoming webhook" rule that creates an issue. This works and costs nothing.

What you have to build yourself: avoiding a new issue every day once the threshold is passed, starting again after a renewal, noticing that the script itself has stopped running, and keeping the host list somewhere people can edit it.

Option 3: Expiry Tracker

Expiry Tracker is a Jira app that does the second option for you and keeps the list inside Jira.

  1. Add each certificate as an item: a name, the host (optionally with a port, such as host:8443) and an owner.
  2. On the settings page, create an agent token and follow the three commands shown there. They install a small open-source shell script on one Linux machine in your network. It needs only sh, curl and openssl.
  3. Once a day the script asks Expiry Tracker which hosts to check, reads each certificate and reports the dates back.

From then on the app creates one Jira issue per certificate 60, 30 and 7 days before expiry (you can change the numbers), assigned to the owner, in the project you choose. After a renewal the reminders start again for the new date.

Why a script on your side: Atlassian apps are not allowed to open connections to your servers. The script runs inside your network, so it also reads certificates on internal hosts and certificates from a private CA. Nothing but host names, ports and dates is exchanged.

What it does not do: it does not renew certificates, and it does not find hosts by itself. You add them to the list.

If the script stops reporting for 48 hours, the app opens an issue about that too, so a dead cron job does not turn into a missed renewal.
